  preprocessing + accumulated M-FARS updates

  500 nodes | RANDOM_SMALL             | break-even at <= 5 updates

METHODOLOGY:
1. One graph is generated for each experiment.
2. M-FARS preprocessing is paid exactly once.
3. Multiple updates are applied to that SAME graph.
4. Dijkstra is rerun after every update.
5. Dijkstra remains the correctness oracle.
6. Verification time is not counted as M-FARS update time.
7. Amortized M-FARS time = preprocessing + all M-FARS updates.
8. Work reduction uses edge-relaxation counts.

NOTE:
V1.4 is designed to test whether the preprocessing cost is recovered over repeated dynamic updates.
